
## Tableau Humain

> **Pilotage Spec-Driven — rév. 2026-11-26 (v3)** : toutes les vues dynamiques de cette page lisent le **registre canonique `01-Principes_Spécifications/registry_exigences.json`** (index machine unique, Règle 2 du §7) et normalisent les UIDs **sans casse**. Les frontmatters des specs restent la déclaration humaine ; le registre fait foi.

### À quoi sert cette page — le superviseur du cycle en V

Dans le cycle en V, chaque exigence descend (spécification → conception → code) puis doit remonter prouvée (recette → validation → clôture arbitrée). Cette page est le **poste de pilotage de cette traçabilité bilatérale** : elle ne produit rien, elle répond aux questions que seul un humain peut trancher.

| Question de pilotage (V) | Vue qui répond | Action attendue du superviseur |
| :--- | :--- | :--- |
| « Peut-on committer / clôturer l'étape ? » | Dashboard | Si couverture en baisse ou orphelins en hausse : geste correctif AVANT clôture ; clôture = 100% recetté ou arbitrage documenté (GOU_4) |
| « Le budget d'exigences de la vague est-il tenu ? » | §2 Table + répartition | Compter les EXG par phase/lot avant d'ouvrir ; split au cadrage si > ~10 |
| « La vague avance-t-elle à spécification constante ? » | §4 + §4.bis Couverture | Traiter les « non couverts » (hors visuelle/inspection/prevue légitimes) ou les ré-porter avec motif |
| « Le front reste-t-il un adaptateur pur ? » | §4.bis Ventilation backend/front | Toute exigence métier ancrée dans le front = dérive de la loi brique/application : à corriger côté back |
| « Le dette de traçabilité grossit-elle ? » | §5 Orphelins | Relier chaque orphelin au registre (UID en docstring) ou l'abroger |
| « Le design dérive-t-il de la spec ? » | §6 Canvas | Sections fantômes → recalage ; exigences sans section → conception à produire |
| « Quels invariants gouvernent le corpus ? » | §7 Règles | Contrat : ces règles s'imposent, y compris à cette page |

## Dashboard

> **Objet :** photographie instantanée du pilotage — volume d'exigences du registre, couverture par test, orphelins de traçabilité, répartition par recette (auto/visuelle/inspection/prevue) et ventilation backend/frontend.
> **Impact superviseur :** 30 secondes pour répondre « l'étape est-elle recettable, le front reste-t-il pur, la dette grossit-elle ? ». Toute dérive (couverture en baisse, orphelin nouveau, exigence qualifiée *prevue* qui traîne) déclenche un geste correctif avant tout commit de clôture.

```dataviewjs
(async () => {
    // SSOT : le registre canonique (Règle 2 du §7) — jamais le frontmatter des specs
    const REG_PATH = "01-Principes_Spécifications/registry_exigences.json";
    const norm = s => String(s || "").trim().toUpperCase();
    const regFile = app.vault.getAbstractFileByPath(REG_PATH);
    if (!regFile) { dv.paragraph("⚠️ Registre canonique introuvable : " + REG_PATH); return; }
    const reg = JSON.parse(await app.vault.read(regFile));
    const exigences = reg.exigences || [];
    const byId = new Map(exigences.map(e => [norm(e.id), e]));
    const totalExgs = exigences.length;

    // Répartition par recette (gouvernance : auto / visuelle / inspection / prevue)
    const parRecette = {};
    for (const e of exigences) {
        const r = (e.recette || "-").split(" ")[0].toLowerCase();
        parRecette[r] = (parRecette[r] || 0) + 1;
    }

    // Scan des tests — matching INSENSIBLE À LA CASSE (leçon reprise : AGE_1 vs age_1)
    let coveredExgs = new Set();
    let orphanFunctionsCount = 0;
    const pyFiles = app.vault.getFiles().filter(f =>
        f.path.includes("03-Application/Test/") && f.path.endsWith(".py"));
    for (const file of pyFiles) {
        const content = await app.vault.read(file);
        (content.match(/EXG-[\w-]+/gi) || []).forEach(id => {
            if (byId.has(norm(id))) coveredExgs.add(norm(id));
        });
        for (const blk of content.split(/(?=def test_)/)) {
            if (!blk.trim().startsWith("def test_")) continue;
            const hits = (blk.match(/EXG-[\w-]+/gi) || []).map(norm).filter(id => byId.has(id));
            if (hits.length === 0) orphanFunctionsCount++;
        }
    }

    const coverageRate = totalExgs > 0 ? ((coveredExgs.size / totalExgs) * 100).toFixed(1) : 0;
    const recetteTxt = Object.entries(parRecette).sort()
        .map(([k, v]) => `${k}: ${v}`).join(" · ");

    // Ventilation backend / frontend : ancres EXG par nature de fichier (loi brique/application)
    // FIX v3.1 : ne lire QUE des fichiers texte (py/js/html/css) — app.vault.read sur un
    // binaire (modele du cache, image) leve une exception qui tuait tout le bloc.
    const frontIds = new Set(), backIds = new Set();
    const codeFiles = app.vault.getFiles().filter(f =>
        f.path.startsWith("03-Application/") && !f.path.includes("__pycache__") &&
        /\.(py|js|html|css)$/.test(f.path));
    for (const f of codeFiles) {
        let content;
        try { content = await app.vault.read(f); }
        catch (e) { continue; }
        const ids = (content.match(/EXG-[\w-]+/gi) || []).map(norm).filter(id => byId.has(id));
        for (const id of ids) {
            if (/\.(js|html|css)$/.test(f.path)) frontIds.add(id);
            else if (f.path.endsWith(".py") && !f.path.includes("/Test/")) backIds.add(id);
        }
    }
    let BACK = 0, FRONT = 0, FULL = 0, QUALIF = 0;
    let backCovered = 0, backEquipables = 0;
    for (const e of exigences) {
        const id = norm(e.id);
        const rec = (e.recette || "-").split(" ")[0].toLowerCase();
        if (backIds.has(id) && frontIds.has(id)) FULL++;
        else if (backIds.has(id)) BACK++;
        else if (frontIds.has(id)) FRONT++;
        else QUALIF++;
        if (backIds.has(id) || rec === "auto") {
            backEquipables++;
            if (coveredExgs.has(id)) backCovered++;
        }
    }

    dv.paragraph(
`> [!info] **Tableau de Bord Exigences & Traçabilité — source : registre canonique v${(reg.metadata && reg.metadata.spec_driven_version) || "?"}**
> - 📋 **Total Exigences (registre) :** \`${totalExgs}\` — par recette : ${recetteTxt}
> - 🎯 **Couvertes par un test :** \`${coveredExgs.size} (${coverageRate}%)\`
> - ⚠️ **Non couvertes** (visuelle/inspection/prevue incluses) : \`${totalExgs - coveredExgs.size}\`
> - 🧩 **Fonctions de test sans UID registre :** \`${orphanFunctionsCount}\`
> - 🧮 **Ventilation cible (ancrages code) :** \`BACK ${BACK} · FRONT ${FRONT} · FULL ${FULL} · à qualifier ${QUALIF}\`
> - ⚙️ **Couverture backend (tests pytest) :** \`${backCovered}/${backEquipables}\`
> *(Plancher NonReg courant : 130 passed. Un FRONT > 0 sur une exigence métier = dérive loi brique/application — cf. §4.bis. Les « à qualifier » sont majoritairement des recettes visuelles/inspection sans ancrage code scannable.)*`);
})();
```

### 1. Cartographie des Spécifications

> **Objet :** vérifier que les spécifications écrites dans chaque phase sont bien **présentes** (une phase = ses specs), et livrer une **synthèse compréhensible par l'humain**. Le statut affiché est un **lookup dans la Roadmap** (la Roadmap fait foi) : le frontmatter `statut` des specs est secondaire, il ne doit plus jamais être la source affichée.
> **Impact superviseur :** repérer avant cadrage les phases actives sans spec, les specs orphelines (phase absente de la Roadmap, ex. génération abrogée non archivée), et lire d'un coup d'œil l'état réel écrit-par-phase.

```dataviewjs
(async () => {
    // Statut par phase : LOOKUP dans la Roadmap (la roadmap fait foi) — jamais le frontmatter des specs
    const ROADMAP = app.vault.getAbstractFileByPath("00-Projet/Roadmap.md");
    if (!ROADMAP) { dv.paragraph("⚠️ 00-Projet/Roadmap.md introuvable : lookup impossible."); return; }
    const txt = await app.vault.read(ROADMAP);
    // Lignes de table "| **P8** | … | 🟢 **PASSED** |" (phases) — le statut est la cellule à badge
    const phaseStatut = {};
    for (const line of txt.split("\n")) {
        if (!/^\|\s*\*\*P\d+\*\*/.test(line)) continue;
        // statut = DERNIERE cellule du la ligne de phase (robuste aux accents et qualifycatifs)
        const ph = line.match(/\*\*(P\d+)\*\*/);
        const cell = line.match(/\|\s*(🟢|🟡|⚪|📝|🔴|🔵)([^\|]*)\|\s*$/);
        if (ph && cell) phaseStatut[ph[1].toUpperCase()] = {
            badge: cell[1],
            statut: cell[2].replace(/\*\*/g, "").trim().toUpperCase()
        };
    }
    const lookup = p => phaseStatut[String(p || "").toUpperCase()] || null;

    // Specs vivantes (declaration humaine) : reference, phase, titre, description
    const specPages = dv.pages().where(p => p.type === "spec");
    const rows = [], anomalies = [];
    const parPhase = {};
    for (const page of specPages) {
        const ref = page.reference || page.file.name;
        const ph = String(page.phase_code || "").toUpperCase();
        const st = lookup(ph);
        let statutTxt;
        if (!ph) { statutTxt = "⚠️ sans phase_code"; anomalies.push(`${ref} : sans phase_code`); }
        else if (!st) { statutTxt = "🔴 phase absente de la Roadmap"; anomalies.push(`${ref} : phase ${ph} absente de la Roadmap`); }
        else statutTxt = `${st.badge} ${st.statut}`;
        (parPhase[ph || "—"] = parPhase[ph || "—"] || []).push(ref);
        let desc = String(page.description || "").replace(/\r?\n/g, " ").slice(0, 120);
        // Gardien metadonnees (Regle 8 §7) : titre fonctionnel present et court, description pourvue
        const titreRaw = String(page.titre || page.file.name).trim();
        if (!page.titre || titreRaw.length < 8)
            anomalies.push(`${ref} : titre fonctionnel absent/trop court (Regle 8)`);
        if (titreRaw.length > 60)
            anomalies.push(`${ref} : titre > 60 caracteres (Regle 8)`);
        const descLen = String(page.description || "").replace(/\r?\n/g, " ").trim().length;
        if (descLen < 20)
            anomalies.push(`${ref} : description trop courte (Regle 8)`);
        rows.push([`[[${page.file.path}|${ref}]]`, ph || "-", statutTxt,
                   titreRaw.slice(0, 70), desc + (desc.length >= 120 ? "…" : "")]);
    }
    rows.sort((a, b) => String(a[1]).localeCompare(String(b[1]), "fr", { numeric: true }) || a[0].localeCompare(b[0]));

    // Synthese humaine : une ligne par phase — nb de specs + statut Roadmap
    const phases = Object.keys(parPhase).sort((a, b) => a.localeCompare(b, "fr", { numeric: true }));
    const lignes = phases.map(ph => {
        const st = lookup(ph);
        const n = parPhase[ph].length;
        const base = `**${ph}** : ${n} spec${n > 1 ? "s" : ""}` +
            (st ? ` — statut Roadmap ${st.badge} ${st.statut}` : " — ⚠️ statut Roadmap introuvable");
        return base;
    });
    dv.paragraph("> [!abstract] Synthèse — specs écrites par phase (statuts dérivés de la Roadmap)<br>" + lignes.join("<br>"));

    dv.table(["Spécification", "Phase", "Statut (Roadmap, lookup)", "Titre", "Description"], rows);

    if (anomalies.length)
        dv.paragraph(`> [!warning] **Anomalies (${anomalies.length}) :** ${anomalies.join("<br>")} — à règler avant tout cadrage (gatekeeper étape 0).`);
    else
        dv.paragraph("✅ Chaque spec a une phase connue de la Roadmap ; chaque phase a sa population de specs.");
})();
```

### 4. Couverture des exigences par des tests

> **Objet :** le versant montant du V — chaque exigence confrontée à ses tests et à son régime de recette.
> **Impact superviseur :** distinguer la non-couverture **légitime** (recette `visuelle`/`inspection`, EXG `prevue` avant implémentation) de la **dette** (aucun test, aucune recette) ; à la clôture d'une vague, cette table doit être verte ou son reste ré-porté avec motif.
```dataviewjs
(async () => {
    const REG_PATH = "01-Principes_Spécifications/registry_exigences.json";
    const norm = s => String(s || "").trim().toUpperCase();
    const regFile = app.vault.getAbstractFileByPath(REG_PATH);
    if (!regFile) { dv.paragraph("⚠️ Registre canonique introuvable : " + REG_PATH); return; }
    const reg = JSON.parse(await app.vault.read(regFile));

    // Scan tests + NonReg — matching insensible à la casse
    const testMapping = {};   // UID (haut de casse) -> [fichiers]
    const nonRegMapping = {};
    const pyFiles = app.vault.getFiles().filter(f => f.path.endsWith(".py"));
    for (const file of pyFiles) {
        const content = await app.vault.read(file);
        const hasNonRegMark = /non_regression/i.test(content);
        const unique = [...new Set((content.match(/EXG-[\w-]+/gi) || []).map(norm))];
        for (const id of unique) {
            (testMapping[id] = testMapping[id] || []).push(file.name);
            if (hasNonRegMark) nonRegMapping[id] = true;
        }
    }

    const rows = (reg.exigences || []).map(e => {
        const id = norm(e.id), rec = (e.recette || "-").split(" ")[0];
        const testedBy = testMapping[id] ? testMapping[id].join(", ")
            : (rec === "visuelle" || rec === "inspection") ? "— (recette " + rec + ")" : "⚠️ Non couvert";
        return [
            e.spec_source || "-",
            e.id,
            e.domaine || "-",
            e.core ? "Core" : "Non-Core",
            nonRegMapping[id] ? "✅" : "❌",
            (e.titre || "-").replace(/(\r\n|\n|\r)/gm, " "),
            rec,
            testedBy
        ];
    }).sort((a, b) => a[1].localeCompare(b[1]));

    if (rows.length === 0) { dv.paragraph("⚠️ Registre vide."); return; }
    dv.table(["Spec source", "ID Exigence", "Domaine", "Core/Non-Core", "NonReg",
              "Intitulé", "Recette", "Fichier(s) de Test Associé(s)"], rows);
})();
```

### 4.bis Ventilation Backend / Frontend & Purity Front

> **Objet :** répartir les exigences par cible d'implémentation — BACK (moteurs `core/`, `phases/`, routes API), FRONT (`static/` js/html/css), FULL (ancré des deux côtés) — et montrer la couverture **backend** isolément.
> **Impact superviseur :** tenir la loi brique/application — le front est un **adaptateur pur** : aucune exigence métier ne doit vivre que côté front (un FRONT > 0 sur une EXG métier est une dérive, la logique remonte au back) ; et la dette de test backend apparaît sans être masquée par les recettes visuelles du front.

```dataviewjs
(async () => {
    const REG_PATH = "01-Principes_Spécifications/registry_exigences.json";
    const norm = s => String(s || "").trim().toUpperCase();
    const regFile = app.vault.getAbstractFileByPath(REG_PATH);
    if (!regFile) { dv.paragraph("⚠️ Registre canonique introuvable : " + REG_PATH); return; }
    const reg = JSON.parse(await app.vault.read(regFile));
    const exigences = reg.exigences || [];

    // Ancrages code par nature de fichier — extensions TEXTE uniquement (cf. fix v3.1)
    const frontFiles = [], backFiles = [];
    for (const f of app.vault.getFiles()) {
        if (!f.path.startsWith("03-Application/") || f.path.includes("__pycache__")) continue;
        if (/\.(js|html|css)$/.test(f.path)) frontFiles.push(f);
        else if (f.path.endsWith(".py") && !f.path.includes("/Test/")) backFiles.push(f);
    }
    const scanUids = async files => {
        const s = new Set();
        for (const f of files) {
            let c;
            try { c = await app.vault.read(f); }
            catch (e) { continue; }
            for (const m of c.matchAll(/EXG-[\w-]+/gi)) s.add(norm(m[0]));
        }
        return s;
    };
    const FRONT_IDS = await scanUids(frontFiles);
    const BACK_IDS = await scanUids(backFiles);

    // Tests backend (pytest de Test/)
    const testIds = new Set();
    let testFuncsSansUid = 0;
    for (const f of app.vault.getFiles().filter(f =>
        f.path.startsWith("03-Application/Test/") && f.path.endsWith(".py"))) {
        const c = await app.vault.read(f);
        for (const m of c.matchAll(/EXG-[\w-]+/gi)) testIds.add(norm(m[0]));
        for (const blk of c.split(/(?=def test_)/)) {
            if (blk.trim().startsWith("def test_") &&
                !(blk.match(/EXG-[\w-]+/gi) || []).length) testFuncsSansUid++;
        }
    }

    const rows = [];
    let totBack = 0, backTested = 0, frontPurs = 0, frontSuspects = 0;
    for (const e of exigences) {
        const id = norm(e.id), rec = (e.recette || "-").split(" ")[0].toLowerCase();
        const inF = FRONT_IDS.has(id), inB = BACK_IDS.has(id);
        const cible = inB && inF ? "FULL" : inB ? "BACK" : inF ? "FRONT" : "— (visuelle/inspection)";
        const tested = testIds.has(id);
        const legitime = rec === "visuelle" || rec === "inspection" || rec === "prevue";
        const domaine = e.domaine || "";
        // Exigence métier (non UI) vivant seulement côté front = dérive adaptateur pur
        let alerte = "";
        if (inF && !inB && domaine !== "UI" && !legitime) { alerte = "🔴 métier au front (loi brique/application)"; frontSuspects++; }
        else if (inF && !inB) { frontPurs++; }
        if (inB) { totBack++; if (tested) backTested++; }
        rows.push([
            e.id, cible, domaine, rec,
            inB ? (tested ? "✅ pytest" : (legitime ? "— hors pytest attendu" : "❌ à recetter")) : "—",
            alerte || "✅"
        ]);
    }
    rows.sort((a, b) => a[1].localeCompare(b[1]) || a[0].localeCompare(b[0]));
    dv.table(["ID Exigence", "Cible", "Domaine", "Recette", "Test backend", "Verdict front"], rows);

    dv.paragraph(
`> [!info] KPI ventilation — backend : \`${totBack}\` EXG ancrées backend, \`${backTested}\` testées pytest ; front pur : \`${frontPurs}\` ; dérives métier-au-front : \`${frontSuspects}\` ; fonctions pytest sans UID : \`${testFuncsSansUid}\`
```

### 7. Règles de Sobriété Documentaire (5S, acté 19/11/2026)

> **Objet :** les invariants du corpus — sept règles qui codifient ce que le 5S a arbitré (une vérité = un fichier, une exigence = une déclaration, jamais de copie phases↔core…).
> **Impact superviseur :** le contrat de la page — ces règles s'imposent à toute nouvelle phase ET aux vues dynamiques ci-dessus ; un chiffre du dashboard qui les contredit (doublon, double lecture) est une alerte prioritaire sur la donnée, jamais un bruit à ignorer.

Les règles ci-dessous codifient l'aboutissement du 5S sur le corpus documentaire
(Atelier, specs, données). Elles s'imposent à toute nouvelle phase (P9 et
suivantes) ; les nettoyages du corpus ont été exécutés lors de l'étape de
reprise (close le 2026-11-25, CI vert) avec la non-régression portée au
plancher de **130 tests**, jamais à chaud.

**Règle 1 — Une vérité = un fichier.** Chaque donnée (`.ttl`, shapes SHACL,
requêtes SPARQL) vit en un seul exemplaire : c'est la source de vérité,
manuscrite, jamais dupliquée. Les miroirs `.md` et `.json` des graphes
(`DKG_TBox_Master.md`, `.json`, `DKG_ABox_*.md`, etc.) sont **abrogés**
(arbitrage 19/11, exécuté à la reprise ; chemins SSOT supprimés lors de la
régularisation des constantes). Une vue graphique est
**générée à la demande** par `core/mermaid_views.py` (le moteur de vue, marqué
« généré, ne pas éditer ») — jamais manuscrite. Les exportateurs manuels
(`export_phase*_md.py`) sont archivés.

**Règle 2 — Une génération canonique de spécifications.** Les `SPC-*` de
`01-Principes_Spécifications/` sont la génération canonique vivante ;
`registry_exigences.json` est l'index machine unique. Les générations
antérieures (`05-Bin/SPEC-*`, `06-Archives/Specifications_*`) rejoignent les
archives — pas de maintien parallèle. Une exigence formalisée dans une génération
antérieure qui n'existe pas en SPC-* est soit portée, soit explicitement
abrogée ; jamais laissée en double lecture.

**Règle 3 — Rejeu vs moteurs : jamais de copie.** `phases/PhaseN` = SSOT du
rejeu par phase ; `core/` = SSOT des moteurs partagés ; ni l'un ni l'autre ne
copie l'autre — l'`import` fait le pont (aucun module de `core` n'importe
`phases`, les phases et les tests importent `core` et `phases` in situ). Une
« ventilation par duplication » est une dérive : elle crée des exemplaires
divergents (cas `local_host_scanner.py`, dupliqué core/Phase7).

**Règle 4 — Le tri se recette, il ne se improvise pas.** Tout fichier mort,
redondant ou hors-sol identifié par 5S est traité en phase (spec + NonReg),
classé `06-Archives` plutôt que supprimé quand il porte une valeur de rejeu ou
d'histoire. Le grep d'imports réel
(`grep -rn "from core\.\|import core\|from phases\|import phases" --include="*.py"`)
est la preuve canonique de vie d'un module ; le `__pycache__` n'est preuve que
du passé. En fin de phase, aucun module mort ne survit au tree (Sustain).

**Règle 8 — Métadonnées de spec (acté 26/11).** Une spec porte trois
champs, chacun son métier ; aucun ne remplace l'autre :
- `reference` = **identifiant mécanique immuable** (format
  `SPC-MET|TEC|FWK-P{phase}[-slug-court]_{yy}`). Le slug est un
  aide-mémoire non normatif, **jamais porteur du sens officiel**.
  Renommer une référence est interdit : on abroge la spec (06-Archives)
  et on en pose une nouvelle (cf. arbitrage RGPD du 26/11).
- `titre` = **libellé fonctionnel officiel**, court (≤ 60 caractères),
  unique au sein de la phase ; c'est lui qui s'affiche dans toutes les
  vues de pilotage (synthèses, cartographie, dashboard).
- `description` = **l'objet** de la spec : une à deux phrases
  (pourquoi, périmètre), jamais le comment (qui vit dans le corps).

Gardien : la vue Cartographie (§1) signale automatiquement toute spec
sans titre fonctionnel, avec titre trop long ou description trop
courte — la dette de métadonnées devient visible sans audit manuel.
